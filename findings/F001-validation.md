# F001 — 数値モデルの初回検証結果（2026-10-13）

## これは何を支持するか
運動方程式とその数値積分を比較した**計算上の検証**。物理的な実機セルの挙動や「新しい身体機能」の発見を示すものではない。

## 条件
- 質量 `1 kg`、線形抵抗率 `0.2 s^-1`、時間 `10 s`、初期位置と速度は原則0。
- A: `F=0 N, v0=0`; B: `F=+1 N`; C: `F=-1 N`; D: `F=0 N, v0=1 m/s`。
- B/C等の基本刻み `dt=0.01 s`、収束比較では `0.005 s`, `0.0025 s`。
- モデル：`m dv/dt = F-m gamma v`, `dx/dt=v`。半陰的Euler法。乱数不使用。

## 観測（Python 3.13、リポジトリ用作業コピーのソース、コミット未作成の時点）
| 条件 | 最終位置 [m] | 最終速度 [m/s] | コメント |
|---|---:|---:|---|
| A 静止対照 | 0 | 0 | すべての時刻で静止 |
| B 正方向 | 28.419859835044722 | 4.324677387766583 | 正方向に進んだ |
| C 逆方向 | -28.419859835044722 | -4.324677387766583 | Bの符号反転 |
| D 抵抗で減速 | 4.316028032991051 | 0.1350645224466836 | 1 m/sから減速 |
| E 刻み半減 | 28.4016181368025 | 4.324000373012497 | Bより厳密解に近づく |
| E 刻み1/4 | 28.3924994037761 | 4.323661950219874 | さらに近づく |

- 連続方程式の解析解は、Bの10秒後について `x=28.383382080915318 m`, `v=4.323323583816936 m/s`。
- B/E_half/E_quarterの最終位置誤差は `0.036477754129404`, `0.018236055887183`, `0.009117322860781` m。
- 誤差比は `2.0003094`, `2.0001547`。半陰的Euler法の一次精度と整合。
- Pythonの9件のユニットテストが通過。Wolfram Languageでも連続解および離散モデルの基準値を独立計算し、表示桁の範囲で一致。

## 反証／留保
- 数値計算は解析解に**完全一致しない**。誤差を保存して比較する。
- 1D線形抵抗は現実の接触摩擦・電力消費・複数セル結合を説明しない。
- 初回測定はGit履歴をもたない作業コピーから。GitHubのCIでも同じ比較を実行し、コミット・環境に紐づいたアーティファクトを保存する。

## PR #5 解析解の大きな値に対する数値安定性（2026-10-14）

- 本節は2026-10-13のA〜E初回実験とは別の**回帰テスト・コード修正履歴**であり、上記の初回観測数値を変更しない。
- 旧解析解には`a*t*t*phi2`の積の途中で`inf`が生じる問題があり、CodexがPR #5のP2で報告した。構成`m=1 kg, F=2e304 N, gamma=1 /s, dt=1 s, T=100 s`は有効で、Wolframの連続解は`x≈1.98e306 m`・`v≈2e304 m/s`と有限である。
- さらに`m=1 kg, F=2e307 N, gamma=1000 /s, dt=0.001 s, T=10 s`では、従来の速度項`a*t*phi1`も積の途中でオーバーフローしうるが、Wolframでは`x=1.9998e305 m, v=2e304 m/s`と有限。非常に長い時間・微小な加速度`F=1e-300 N, gamma=1e-200 /s, dt=T=1e200 s`についても、`t*t`の直接計算を経由せず`x≈3.6787944e99 m`を算出する必要がある。
- `soma/f001.py`の`analytic_state()`は`math.frexp`/`math.ldexp`により積の仮数と二進指数を別々に扱い、**数学的には有限な積の途中だけがオーバーフローする事象**を防ぐ。小さい`gamma*t`の`expm1`／Taylor計算や半陰的Eulerの`step()`、初回のA〜E設定は変更していない。
- `tests/test_f001.py`に大きな正負力、強抵抗下の速度、微小力・巨大時間の負例を2テストメソッドとして追加。commit`7befcfb4d3083a1b24364311e5fef9519a0b3702`の[F001 CI #38547923781](https://github.com/ryonakayama234/SOMA-Synthetic-Organism-Morphogenesis-Arena/actions/runs/38547923781)で**15テスト全件合格**した。
- これらは数値的な演算域の健全性検査であり、非現実的な大きさの力を物理実機で扱えることを示すものではない。PR #5は独立レビュー・統合前であり、当時の旧CIと初回観測は履歴として保持する。

## PR #5 符号付き和の中間オーバーフロー（2026-10-14）

- レビュー対象 `c0c509f` では各積が有限でも位置項の加算途中があふれる。再現条件は `m=gamma=dt=T=1`、`x0=7.3e307`、`v0=1.7e308`、`F=-9e306`。修正前のローカル実行で解析位置 `inf` を確認した。
- `_signed_sum()` は通常 `math.fsum` を使い、有限項の途中和で `OverflowError` が出た場合だけ、標準ライブラリ `Fraction` による二進浮動小数点値の厳密な有理数和へ切り替える。各項が有限なときの相殺を保持し、最終結果自体がfloatで表せない場合は符号付き `inf` とする。抵抗ゼロの式も同じ積・和の処理を使う。
- 独立基準は `Decimal` の100桁計算で連続方程式を評価。再現条件の位置は約 `1.7714958003031182e308 m`、速度は約 `5.685041996968817e307 m/s`。正負を反転した条件、時刻0、manifestの解析値・誤差の有限性、抵抗ゼロの相殺、本当に表現範囲を超える結果を回帰テスト2件で検証した。
- Python 3.12.14のローカル実行で **17テスト合格**、A〜Eの6条件を再実行し、位置・速度および刻み半減の収束傾向を確認した。最新コミットのCI証拠は [PR #5 Checks](https://github.com/ryonakayama234/SOMA-Synthetic-Organism-Morphogenesis-Arena/pull/5/checks) で確認する（この記録作成時点では未実行）。
- 今回の保証は有限な各項の加算に対するもの。個々の項そのものが表現範囲を超える場合や、数値積分・SVGを含むすべての極端入力を保証するものではない。初回観測・旧CI証拠は履歴として保持する。
