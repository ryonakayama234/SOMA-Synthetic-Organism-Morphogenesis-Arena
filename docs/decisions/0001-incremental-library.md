# ADR-0001 — 小さな機能と検索可能な図書館

## 背景
研究者は長大な仕様書やGitの詳細ではなく、観測可能な単一機能を一つずつ検討したい。また、後続のAIが過去の前提を失わないことが必要。

## 決定
- READMEを索引とし、理念・構造・データ・研究手順・個別機能・文献を別ファイルにする。
- 図にはMermaidを使い、GitHub上で直接見られるようにする。
- 個別機能はF001,F002…の不変IDを持ち、関連資料・Issue・実験ログを結ぶ。
- 既存コードにない「理想の実装」をあたかも完成した構造のように記述しない。
- 小さな変更も採用理由と反証条件を残し、必要なときのみ抽象化・共通化する。

## 代替案と選ばなかった理由
- 一冊の大きな仕様書：探しにくく、更新時に矛盾が広がりやすい。
- 最初から複雑なマイクロサービス設計：研究テーマの変化に過剰適合し、作り直しの負担が大きい。
- 結果だけ保存：誤った仮説や条件が消え、同じ失敗を繰り返す。

## 見直し条件
資料が増え、検索負荷が実測で高まったときに機械可読な索引生成を検討する。現時点ではYAMLメタデータと相互リンクで十分。
