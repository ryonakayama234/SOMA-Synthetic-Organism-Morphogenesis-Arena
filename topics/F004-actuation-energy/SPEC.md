# F004 研究仕様【実装・検証済み／2026-10-16 採用決定】

**現在の有効範囲**：1セル1Dの離散理想モデルにおける、正の区間モーター仕事とF002残量の接続。ユーザーの採用・統合指示を受け、設計PR #10を先に統合し、実装をPR #11で統合する。下の提案・未実装表示は設計時点の履歴であり、後続の監査補足と末尾の採用条件が優先する。

## 位置づけ
- F001：力を与えた単一セルの1D運動を検証済み。
- F002：整数µJでのエネルギー収支を検証済み。運動とは独立。
- F003：2セルの理想機械結合を検証済み。ここでは利用しない。
- **F004の一能力**：自身のモーターによる運動のみがバッテリーを消費し、残量不足で駆動できなくなる。

## 問い、仮説、対立仮説
**問い**：電池に制約された内部駆動力と電池に属さない外力を区別すると、エネルギー残量が単一セルの1D運動を変えるか。

**H004（仮説）**：一定の内部駆動力を指令するセルについて、定義した離散理想機械仕事の正部分がF002の残高を減らす。残高が足りないステップではモーター力だけ0となり、同一指令でも軌跡が変わる。

**代替・反証**：外力の仕事が電池から差し引かれる、負残量、残量0で内部駆動が働く、台帳残差が非0、後付け条件変更なしには独立離散予測と合わない、保存データを改変しても合格する、など。

## 物理・台帳の最小モデル（設計仮定）
F001の半陰的Eulerを流用。質量 m [kg]、線形速度抵抗係数 g [1/s]、刻み h [s]、初期速度 v [m/s]、内部駆動の指令力 u [N]、外力 f_ext [N] とする。

~~~text
候補速度 v_c = v + h*((u + f_ext)/m - g*v)
候補平均速度 v_avg = (v + v_c)/2
候補内部仕事 W_motor = u*h*v_avg [J]
候補消費 c_uj = ceil(1,000,000 * max(0, W_motor))
~~~

- ただし u=0 または c_uj=0 ならF002支出イベントを発生させない（F002は支出額に正の整数を要求）。
- c_uj が現在残高以下なら、F001の力 u+f_ext を適用し、F002の spend イベントで c_uj を控除。足りなければ **当該ステップに限り内部力を0**とし、F001で外力 f_ext だけを適用する。電池は不変。
- 正の1µJ未満の仕事も1µJ支出となる。切り上げによる差は理想仕事に対する数量化差として別に記録。
- 初期モデルは**効率100%・回生なし・静止時保持／待機消費なし**。負のモーター仕事は「電池へ戻らない理想ブレーキ」とする。実機の駆動機構・回生・熱損失モデルを主張しない。
- 候補仕事の符号とエネルギー量は**台形速度近似**で定める。位置はF001の半陰的Eulerによる x_next=x+h*v_next とするため、位置差*力と台形仕事は一般に一致しない。別々の量として記録する。
- 物理更新・支出は一つのステップの成功として不可分に確定。バリデーション例外が発生した場合、そのステップの世界状態と台帳をどちらも更新しない。セルの視点に世界の真値を渡さない。

## 独立の代数チェック（Wolframで2026-10-15に検算した理論恒等式）
v_next = v + h*((u_applied+f_ext)/m - g*v)、v_mid=(v+v_next)/2 とすれば、

~~~text
K_next-K = W_motor + W_external - W_drag
K = m*v^2/2
W_motor = u_applied*h*v_mid
W_external = f_ext*h*v_mid
W_drag = m*g*v*h*v_mid  （符号付きの離散項）
~~~

上式の残差は記号的に0。W_dragは刻み中の速度反転がある場合には常に正とは限らず、「実際の熱散逸が常に正」と同一視しない。整数µJ切り上げ分は上の機械式の外にあり、台帳上の支出と理想仕事の差として扱う。

## 対象範囲
**対象**：1セル1D、時間一定の u / f_ext、F001の運動更新、F002の残高とspend記帳、実行証拠と対照比較。

**非対象**：F003への物理接続、二セルでの電源共有、モーターの実測効率、押しつけ力・衝突・荷重、知覚・学習・自律的結合、資源探索、生存競争、進化。

## 2026-10-16 設計監査・実装契約 v0.2（上の提案に優先、まだ未実装）

### 発見した欠陥と修正方針
**P1／残高0でゼロ仕事モーターが動く抜け道**：u=1 N、外力=-1 N、初速0、残高0では候補速度0、内部仕事0、候補支出0。旧「費用 <= 残高」の条件のみではモーター力+1 Nが適用されてしまう（Wolframで反例確認）。**最優先条件として、残高0なら指令uの符号・候補仕事にかかわらず適用モーター力を0**とする。外力は維持する。正の残高で内部仕事が0または負の場合には、100%理想・非回生・待機電力ゼロという今回限定のモデルでは支出を0とする。これは現実の停動時／保持トルク電力を表現しない。

**P1／µJ切上げとIEEE754丸め**：Wolframの有理数計算でBの理論消費500000 µJ、Dの理論残高55000 µJだが、F001と同等のbinary64離散状態に対して各ステップの正の仕事を**そのままmath.ceil**するとBの消費500005 µJ（最終499995 µJ）、Dの最終54996 µJになる。差は丸め順序と1 µJ単位への各ステップ切上げに由来し、台帳不整合ではない。後から予測値を「実験に合う値」へ変更してはいけないため、計算方式を実装前に固定し、**数学的理想値と実装用の浮動小数点参照値を区別**する。両方を実験報告する。

### ステップの厳密な実装順序
1. Configにmass_kg、drag_per_s、dt_s、duration_s、initial_x_m、initial_v_m_s、motor_force_n、external_force_n、capacity_uj、initial_balance_uj、schema_version、experiment_id、seed=nullを持たせる。1セルID固定A。F002の容量限界に従いF004は最大10,000ステップ。dt刻みは十進有理数の厳密整数判定（F003と同方式）。finite値・サイズ・適切な文字を開始前に検査。
2. 各ステップは世界のMotionStateとF002のimmutable LedgerStateを**一組**で受け取る。残量0または指令力0なら内部適用力0でF001.stepを計算、支出0。
3. 残量正かつ指令力非ゼロなら、F001.stepにu + f_extを与えて候補(x_candidate,v_candidate)を計算する。候補・派生量すべて有限でなければ状態変更せず拒否。
4. 候補仕事を**固定した演算順序**で計算する：`w_j = (u * dt_s) * ((v_old + v_candidate) / 2)`（IEEE754 binary64）、`cost_uj = math.ceil(max(0.0,w_j) * 1_000_000)`。積、派生量のoverflow・非有限を正常ログに保存しない。**境界のepsilonスナップは行わない。** B/Dの期待値はこの式に対応する。
5. cost_uj <= balance_ujなら候補運動採用。cost_uj>0のときだけF002.apply_event(spend)によりLedgerStateとEntryを作る。cost_uj=0なら支出なしで採用（残量は正）。cost_uj>balance_ujなら内部力0でF001.stepを**再計算**し、台帳支出なし、残量不変。
6. 状態・台帳・イベント・ログの全フィールドの検証が成功してから、一つのステップとして両状態を確定する。例外時にどちらも変更せず、既存runの証拠も上書きしない。明示的拒否理由を保持する。
7. CSVで`step_index`、`ledger_event_index`（支出なしはnull）、指令力、適用力、外力、速度・位置・残高、候補仕事、支出µJ、分岐理由を保存。位置はF001のsemi-implicit Euler、仕事は速度の台形則。**両者を混同しない。**

### 後続へ持ち越す制限
正の仕事のみ課金するため、残量正・モーター静止トルクなどのゼロ仕事は無償となる。これを「実際のモーターは電力不要」と解釈しない。待機・保持・電気効率の測定モデルは別機能。質量・力・摩擦の実測妥当性も対象外。

### 達成の定量ゲート（監査更新）
- A〜Eの1秒後位置・速度はPLANの理論値との誤差1e-12以下（1D基準条件）。Bの最終残高**499995 µJ**、Dの最終残高**54996 µJ**は、上記binary64の費用計算に関する事前参照（理想有理数値500000／55000との乖離も別記）。
- 全ステップで機械エネルギー収支の残差について独立の再計算ができること。binary64の算術誤差として絶対1e-10 J以下（1D基準条件）。F002整数会計残差は全イベントで**厳密0 µJ**。
- 空電池+非ゼロu+逆方向外力の**候補仕事0**を含む抜け道ケースで`motor_applied_n=0`。外力のみの運動が維持される。
- F004に伴う既存モジュールの公開API変更を禁止。3既存機能の回帰、独立の予測式／保存ログ突合せ、成果物・source SHA、再実行一致、任意の保存証拠改変の検知を採用前の必須ゲートとする。

## 2026-10-16 PR #11 実装監査による受入条件の補完

4件のP2を再現し修正する。物理モデルとA〜Eの事前予測値は維持する。

1. **時間格子の正規化でステップ数を変えない**：生入力では整数比でもfloat保存後の十進比が変わる設定は`ValueError`。rawと正規化後で同じ厳密整数比1〜10000を要求し、`steps`の切り捨てによる短縮実行を防ぐ。
2. **構築経路で検証を迂回できない**：Configの直接生成・`dataclasses.replace`にもJSON/dictと同じ検証を適用する。オフグリッド・無効型・範囲外はシミュレーション前に拒否する。
3. **有限な状態を有限な図へ変換する**：時間比・状態範囲を正規化してから座標へ変換する。有限な入力から表示用中間積や差だけがoverflowして不正SVGを保存することを防ぐ。
4. **保存証拠の全必須項目を照合する**：manifestは必須4成果物すべてのhashを要求する。初期行の全仕事・運動エネルギー差・残差は0と独立照合し、CSVのhashを更新しただけでは意味の不正を通過させない。

これらは既存の有限性・厳密格子・全時刻照合ゲートの不足を補う修正であり、仮説の採用やmain統合の判断ではない。監査後の実行結果は[検証ノート](../../findings/F004-validation.md)で確認する。
